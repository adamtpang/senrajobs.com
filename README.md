# Senra Jobs

A free directory of David Senra interview guests, their companies, and indexed jobs.

The directory is generated static HTML. The optional assistant uses one queued API endpoint and a local subscription-backed Claude/Codex worker.

## Update the site

1. Research new guests and careers links in `GUESTS.md`, the source of truth.
2. Run `node build.mjs` to compile guest data.
3. Run `node fetch-jobs.mjs` to refresh public company boards and portraits.
4. Run `node build.mjs` again to generate the page from refreshed data.
5. Run `node scripts/check-board.mjs`.
6. Run `node scripts/check-sorting.mjs` and `node scripts/check-locations.mjs`.

For a new episode, refresh only its companies with `node fetch-jobs.mjs --guest="Ari Emanuel"` after the first build. Other company feeds are preserved. Verified careers portals on unsupported ATS systems remain link-only; MARI currently uses HiBob.

For one existing employer, use `node fetch-jobs.mjs --company="RXO"` with the exact registry name. This preserves every other employer feed; do not combine it with `--guest`.

Edit `template.html` for layout, `board.js` for job search and browser behavior, and `board-data.mjs` for role aggregation. Do not hand-edit generated `index.html` or `guests.json`.

Run `node scripts/audit-coverage.mjs` after building to reconcile the current registry with the official interview feed. It writes a working audit to `.cache/coverage-current/`, including the observed feed, source hashes, unresolved guests, all recorded associations (including historical/successor gaps), board pagination receipts and a readable `AUDIT.html`. This replaces reliance on dated audit totals; it does not certify exhaustive employer coverage. A new unmatched guest fails reconciliation rather than silently disappearing. `--feed=path` permits offline inspection but explicitly carries no new observation timestamp. Parent/brand role counts overlap; the global URL total is deduplicated. Check the census and association logic with `node scripts/check-guest-census.mjs` and `node scripts/check-coverage-associations.mjs`.

## Assistant beta

Footer WhatsApp feedback links directly to the public contact Adam supplied. The former feedback form, client script and public write API were removed from deployment. Existing encrypted feedback remains private and can be read with `node scripts/read-feedback.mjs`; its output must not be published. Old feedback source/tools are retained locally for existing data, excluded from production. The footer also links to adampang.com as a small creator credit.

`npm run dev` serves the public directory and queue API at http://127.0.0.1:4173. `npm run worker` runs the local inference worker. Production uses the same encrypted queue; the assistant shows unavailable when the worker has no recent heartbeat. The directory remains usable independently. `.env.worker.local` holds ignored queue credentials; never upload it or CLI authentication.

The assistant opens from a floating Find my role control at the bottom corner, leaving the guest grid first. Its launcher hides while the panel is open, and the panel occupies that bottom corner. Close or Escape restores the launcher and preserves the conversation. Enter sends an answer; Shift+Enter inserts a newline; composition and repeated-key events do not submit. The structured interview starts with a question and follows eight sections: direction, experience, skills, results, work environment, practical needs, learning and priorities. It asks focused follow-ups until each area has evidence or was explicitly skipped. Section labels and questions stay aligned. After completion users review a plain-language summary and choose Find my matches. Corrections use the same textbox. JSON/download/update/clear/save controls and profile import were removed from the UI. The generic external-AI prompt remains at `/interview-prompt.txt`, independently of the simplified frontend. Guest/company browsing has no search field; role search remains.

The interview shows a section progress bar and an initial estimated12–15 minutes, decreasing with covered sections. The estimate is a design target, not calibrated completion data. Users can paste résumé text into the same textbox; supported facts can cover several sections. The interviewer asks about ownership, dates, scale, evidence, practical essentials and trade-offs without presenting internal schemas or profile utilities.

The matcher searches the entire index using role/location/pay preferences plus private description/skill relevance, then asks local AI to select and assess up to8 roles from up to36 candidates. A diverse candidate pool avoids filling every slot from one large employer. Numerical fit uses five criteria: skills30, experience/results25, direction/learning20, environment15 and practical preferences10. A supported rating requires exact candidate and employer evidence quotes. Missing or unanchored criteria widen a score range; missing skill/experience evidence prevents a numerical assessment. Unverified practical constraints cannot receive a full practical score. S90+, A80+, B65+, C50+, D below50; a range crossing tiers remains provisional instead of being classified as a poor fit. S also requires fresh evidence, high confidence, no unresolved essential gaps and supported core requirements. These are estimated alignment scores, not hiring probabilities or verified candidate qualifications. Source anchoring does not prove the model's semantic comparison is correct. Tiers and criteria remain reviewable.

After matching, Explore all roles opens the full directory with assessed roles first. Any other catalog role can be assessed on demand with the same profile and rubric; other roles have no fabricated fit numbers. Known incompatible preferences return a clear message. Target URLs must resolve to an indexed role before any source fetch; failed requests refund credits. Profile corrections invalidate prior browser fit results. Each individual assessment uses the existing3-credit match cost. US-remote possibilities for Texas profiles are retained with explicit eligibility uncertainty. Known closed listings are excluded. Unsupported portals remain link-only. `node scripts/enrich-matching.mjs` refreshes private descriptions from supported feeds. Run `node scripts/check-fit.mjs` and `node scripts/check-target-fit.mjs` for rubric guards and real individual-role checks.

Anonymous interview context stays in page memory; closing chat preserves it, refreshing a page does not save a new profile. Existing previously opted-in device profiles can still be read, but the new UI does not write profiles to localStorage. Account sign-in and cross-device saving are not implemented. Queue request/result content expires after24h. Personal profiles never enter generated HTML or production artifacts. Browsing follows guest → company → roles. View, Sort and Filter controls and company search were removed at the user's request; role search remains. Guest cards show company logos and hover/focus feedback. Guest pages show only the name, back link and company rows. Companies without indexed roles link directly to verified careers pages. Existing sorting/filter URLs and source-location links remain supported. Recommendation explanations remain collapsed.

The Sage API remains available for source-backed counsel, but its separate form was removed from the simplified frontend. Source retrieval uses a broad topic from Summon's public synthesis notes; candidate answers and the actual question are never sent to Summon. Coverage is partial, not a full-transcript corpus or a simulation of David Senra.

Anonymous beta sessions receive 12 welcome credits and 5 daily credits (UTC). Each interview/Sage answer uses 1; a shortlist uses 3. Reservations and refunds are transactional, failed/cancelled requests are refunded, and a unique index permits only one active job per session. Requests/results are encrypted with job-bound AES-GCM, cookie access is signed and session-bound, and content expires after 24 hours. The worker and status checks purge expired rows. A session/IP request cap and a global beta cap limit load; anonymous cookies are not a paid account identity. Paid packs and durable accounts are not implemented.

Local CLI inference runs with tools disabled, project/user configuration ignored, and paid API credentials cleared. The worker uses `claude_local` first and `codex_local` as fallback. It runs only while this computer is awake; no automatic boot task is installed. Model-provider retention policies apply separately from the queue's retention.

Run `npm run check:assistant`, `node scripts/check-assistant-queue.mjs` (with worker paused), and `node scripts/check-profile-flow.mjs` for meaningful checks. The profile-flow check uses only a fictional candidate and actual local inference to verify follow-up questions, accumulated professional evidence, tiered ranking, session isolation, credits and deletion. Set `SENRA_TEST_ORIGIN=https://senrajobs.com` to test production. Never run these with private candidate information in logs.

`node scripts/prepare-production.mjs` assembles a public-only artifact and bundles just the queue endpoint. Deploy the folder recorded in `reports/assistant-deployment-artifact.txt`, never the entire checkout. The private worker, credentials, prompts, source documents and `.cache/job-content.json` are excluded.

Jobs are deduplicated by application URL. Several guests can share one company and job. Some sources cap results, so counts describe indexed roles, not complete company hiring totals. A failed refresh retains the previous board and its original timestamp; successful empty feeds remove prior roles. Refreshing remains manual.

The page begins with a guest portrait grid. Selecting a guest replaces it with their company list; selecting any company opens a flat role list. Back links and browser Back restore the previous selection, search, sort, pagination and scroll position. Acquired or closed company associations stay in the research data and are excluded from browsing. Companies with no indexed roles show a short empty state and one official careers link when available; zero indexed roles does not imply the company is not hiring.

Guests, Companies and Roles buttons jump to an unscoped view independently of sorting. View, sort and filter controls sit on the right. Search is available in each view; location, role-title and pay filters appear only in Roles. A single Clear filters action appears when filters are active and preserves the selected guest/company and sort. Role rows show a title with a decorative emoji, location and published salary, with company context when browsing across companies. Role titles link directly to applications. Source and coverage explanations sit in a collapsed About these roles disclosure below the list. Dates appear in the footer. No guest or company accordions are used.

The build embeds the controls and helpers with their page data, avoiding separate script-cache or module-loading dependencies in previews. View, guest, company, search, sort and filter URLs can be shared. Without JavaScript, a careers directory is available below the guest grid.

Location discovery uses published job fields, including secondary locations and provided address metadata. Raw labels, source URLs, timestamps and source status are preserved. Headquarters and company biographies never supply a job location. Missing or opaque multiple-location labels trigger up to 75 official detail/JobPosting checks per board; unresolved records display `Location unknown`. Typing `Texas` or `TX` in the existing location filter matches Texas state tokens and known Texas city names. City-only shorthand should be confirmed on the official posting. `US remote` is a separate possibilities filter that requires explicit US/remote evidence and does not establish Texas eligibility. `Location unknown` exposes unresolved records. Example: `/?view=roles&location=Texas`.

The refresh screens every active research company, including bounded `/careers` and `/jobs` discovery on known official domains when no careers URL is recorded. ATS account identity must match the employer; portfolio-company boards are rejected. Atoms/CSS is mapped from `atoms.co` to the official `atoms` Greenhouse board; `atoms.com` is unrelated footwear. Supported sources paginate up to 500 pages per board. Workable widgets without verifiable totals stay partial. Listing completeness and location completeness are recorded separately. Failed sources retain dated prior data; partial listing responses retain unobserved prior URLs with a stale marker. Fresh complete empty feeds remove prior live postings.

Build exports `data/texas-roles.json`, `data/texas-roles.csv`, `data/coverage.json` and `reports/coverage.md`. The CSV includes Austin membership, published locations, employer links and source status. These contain public role/company/founder data only. Coverage is complete, partial, failed or link-only per employer, with counts, pagination, timestamps, missing locations and reasons. The inventory is not exhaustive; unpublished jobs, unsupported systems, blocked pages and bounded detail retrieval remain limitations. Dollar-glyph salary text with an explicit annual period is preserved as a published range with unspecified ISO currency, rather than inventing USD or mixing it into normalized pay rankings. Dates on stale records remain visible. No candidate information is collected, and no storage keys or saved-job behavior are changed. This checkout currently has no saved-job control.

Ashby and Lever refreshes retain structured salary data when published. Pay sorting uses the advertised upper bound and compares only the selected currency and period; other currencies, intervals, lower-bound-only ranges and undisclosed pay follow. Equity and bonuses are excluded from salary rankings. No currency conversion, annualization or estimated compensation is used. Other feeds may have pay on their application pages that is not currently indexed.

Company marks are cached in `logos/`, mapped by company name in `company-logos.json`. Current brand icons come from public site favicons or the company careers board. Companies without an available mark show initials. Role emojis are decorative title-based hints from `role-emoji.mjs`; they do not affect search or role analytics.

PostHog uses the shared fleet project token. Custom production events cover directory search result counts, empty results, guest and company selection, view changes, sorting and role application clicks. Search text is not included in event properties. A project-side event query is still required to prove receipt after deployment.

AI matching uses the authorized subscription-backed local Claude/Codex worker. No funded API key is required.

Private requirement collection: `node scripts/collect-employer-content.mjs --company="Shopify" --limit=150` reads missing descriptions for an exact current catalog company (omit `--company` for all companies). Each invocation is bounded to 1–500 roles and two concurrent public requests. It writes only to ignored `.cache/job-content.json` and dated collection receipts. Shopify detail IDs and titles must match a published, listed posting; Dell uses external-description fields only and validates the requisition ID/title; The Boring Company uses matching public title/description metadata. Failed parsing does not establish a closed vacancy. Description collection is separate from candidate assessment and public-board completeness. Run `node scripts/check-employer-content.mjs` and `node scripts/check-employer-feeds.mjs` after changing these parsers.

Shopify's separately linked internship, APM and design-apprenticeship channels were reviewed on October 26, 2026; source receipts and timing conflicts are recorded in `reports/shopify-program-channels-2026-10-26.json`. Program landing pages and notification signup routes are not counted as open roles.
