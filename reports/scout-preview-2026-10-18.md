# Scout preview

Implemented in the separate local vision preview at http://127.0.0.1:4187/. Production was not changed. The user selected “No—prepare the setup instructions” for the missing Clerk application.

Scout replaces the generic two-question search interview with provider-neutral starters: Build my career brief, Find roles that fit me, and Learn before I build. ChatGPT, Claude and another-AI choices determine the handoff link; the underlying guide is portable. Copying a starter includes the full guide and current public browsing context, so it works without a cloud AI fetching localhost. Users manually share their selected résumé/chat context. No AI history is accessed through OAuth and no brief is automatically transferred to another provider.

Source documentation: docs/scout-agent-guide.md. The preview build copies it to /agents.md, and /llms.txt points to it and /roles.csv. The CSV contains 10,331 unique public-source role URLs and coverage/freshness fields; it is approximately 2.98 MB. Guide instructions require user confirmation, evidence/inference separation, decision-changing follow-ups, hard-constraint checks, verified requirements, honest search scope and no invented hiring probabilities. Protected characteristics are excluded from ranking.

The user can paste a readable confirmed career brief and shortlist back into Scout. Pasted markup is inert text. Matching catalog URLs become role-detail buttons. Unknown links are not promoted into the catalog. Brief text stays in page memory, clears on reload, and is not written to storage or sent to the server. This is a handoff and review workflow, not a locally executed LLM or an independent verification of AI judgments.

Sign-in has a lazy Clerk JavaScript client integration and a /auth-config.json endpoint exposing only a validated public publishable key, when configured in the preview server environment. No key or Clerk application exists yet, so the preview explicitly says Google sign-in and cloud profile saving are unavailable. No Clerk scripts load in that state. OAuth is untested with real credentials. The account setup and remaining private profile backend work are documented in docs/scout-auth-setup.md. Adding a publishable key does not implement profile persistence.

Verification: app.js and scout.js parse; CSV row count and URL uniqueness pass. ## Superseding update: simple prompt, real matching, private context storage

The three starter buttons are replaced by an AI selector, visible professional-report prompt, one Copy prompt button and an always-visible response box. Report instructions cover all eight professional areas and request detailed evidence-backed progress summaries. Find my matches now calls the existing encrypted local-AI queue rather than merely parsing returned URLs. It extracts a profile, asks a focused follow-up when needed, and runs the real catalog matcher. The UI shows actual pending/running/completed stages and returned search counts, criterion explanations, gaps and next steps.

Added api/profile.mjs, assistant/scout-auth.mjs and assistant/scout-store.mjs. Added jose as a dependency. Private senra_scout_profiles storage uses a dedicated AES-GCM key and account-bound authenticated data. The key is in the existing ignored local worker config and was never displayed. Ownership derives from issuer + subject verified through RS256/JWKS session checks, expiry/not-before/max age, authorized-party origin and non-pending session state. Conditional versions prevent conflicting saves and stale resurrection after deletion. The API is no-store and has bounded input. No user ID in request content controls ownership.

Signed-in submitted reports, extracted profiles, shortlisted URLs and browsing filters save and restore; signed-out reports stay in page memory. Login does not silently overwrite an existing saved report with an anonymous draft. Account switching clears page and transient queue context. Account deletion control removes saved payload, retaining only revision metadata. Google/Clerk remains unconfigured, so this integration is disabled for real users until CLERK_PUBLISHABLE_KEY and CLERK_ISSUER are supplied. No real OAuth completion or production deployment is claimed.
